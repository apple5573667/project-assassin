# PROJECT ASSASSIN · 실시간 파티 게임 사이트

15~20인 모임용 (기술적으로 6명부터 시작 가능, 권장 최소 8명). 휴대폰 브라우저에서 방 링크에 접속해 개인 암살 미션을 확인하고, 양방향 동의 방식으로 상호작용을 기록하는 실시간 웹 앱입니다.

## 바로 실행하기

Node.js 18 이상을 설치한 뒤 폴더에서:

```bash
npm start
```

브라우저에서 `http://localhost:3000` 접속. 같은 와이파이의 다른 기기에서 테스트하려면 PC의 LAN IP와 `3000` 포트를 사용하세요(방화벽 설정 필요). **외부 사람에게 링크를 공유하려면 배포가 필요합니다.**

## 배포 방법 (Render 예시)

1. 이 폴더 내용을 GitHub 저장소에 올립니다.
2. Render.com에서 **New > Web Service** → 해당 GitHub 저장소 연결.
3. Runtime `Node`, Build Command `npm install`, Start Command `npm start` 설정. 또는 `render.yaml`을 사용하는 Blueprint 배포도 가능합니다.
4. 배포 후 제공되는 `https://...onrender.com` 주소로 접속해 **새 게임 방 만들기**를 누릅니다.
5. GM은 사이트에서 나오는 **6자리 PIN**을 보관하고, **방 공유 링크**를 6~20명에게 전달합니다.
6. 참여자는 닉네임만 등록하면 자동으로 방에 들어옵니다. 같은 브라우저로 다시 접속하면 자동 로그인됩니다.

**중요: 무료 Render 서비스는 장시간 미사용 시 잠들 수 있고 재배포/재시작 시 로컬 JSON 데이터가 소실될 수 있습니다.** 실제 행사 전에는 서비스가 켜져 있는지 확인하고, 3라운드 동안 재배포하지 마세요. 안정적 운영을 위해 영구 저장 볼륨을 제공하는 서비스(예: Railway 유료 볼륨, Render 유료 디스크)를 쓰고, `DATA_FILE` 환경변수를 영구 저장 위치로 지정하는 것을 권장합니다. 서버 인스턴스는 **1개만** 실행하세요. 이 앱은 중앙 파일 저장 방식을 사용하므로 다중 인스턴스 간 공유되지 않습니다.

## 실제 진행 순서

1. GM이 방을 만들고 링크 공유. 6~20명 등록 (권장 8~20명).
2. GM `ROUND 1 미션 배정` 클릭. 각 플레이어 화면에 **비밀 암살 대상 1명/암살 행동 1개/개인 미션 1개** 표시.
3. 오프라인에서 선물·질문 카드가 섞인 더미에서 **플레이어당 랜덤 6장** 배부. 모두 본인 폰에서 `미션 확인완료 · 카드 6장 수령` 클릭.
4. GM이 모든 확인 표시를 확인하고 `라운드 시작` 클릭. 실제 10분 타이머는 별도 준비.
5. 다른 플레이어를 만나 4개 행동 중 하나 실행 → **양측 각자의 휴대폰에서 상대 이름과 행동 선택**. 선물/질문은 **누가 전달·질문했는지**까지 일치해야 승인. 악수/교환은 상호적 행동.
6. 모든 상호작용은 **참가자 쌍마다 라운드당 1번**만 확정. 빙고판에 양쪽 동시 표시. 틀리게 제출하면 불일치로 처리돼 서로 다시 선택 가능.
7. 플레이어들은 '암살시도 완료' 버튼 클릭. 모두 제출하면 순위 및 미션 성공 내역 공개. GM은 유사시 강제 종료 가능.
8. GM은 다음 라운드를 시작하고 새로운 대상과 목표를 배정. **총 3라운드**, 최종 누적 순위.

## 점수·밸런스

- 암살: 지정 대상에게 지정된 행동 **1회 성공하면 +5점**. 암살 대상은 라운드마다 새로 배정되며, 매 라운드 모든 사람은 정확히 1명의 암살 대상이 되고, 이전 라운드의 대상은 반복되지 않습니다.
- 개인 목표: 게임 시작 때 **1개** 무작위 지정. 임무 달성 시 +3 또는 +4점. 단순 상호작용 자체로는 점수 없음.
- 개인 목표와 암살 행동의 주된 카테고리는 다르게 배정됩니다.
- 4가지 행동: 선물 카드 1장 전달, 질문 카드 1장 전달 및 답 받기, 서로 악수, 카드 1장씩 교환. 서로 실제 카드 없이 선물·질문·교환 행동을 기록해서는 안 됩니다.
- 선물/질문 카드는 상대에게 물리적으로 전달합니다. 교환은 서로 카드 1장씩 바꿉니다.
- 인원별 거부권: 6~16명 1개, 17~18명 2개, 19~20명 3개. 거부권은 상호작용 완료 전에 사용하며 해당 제안을 취소합니다. 카드/신체접촉에 대한 안전상 거절은 횟수와 관계없이 허용합니다.
- 10분에 20명이라면 각 참가자가 19명을 만나야 하므로 **약 32초마다 1명**과 상호작용해야 합니다. 시간을 늘리지 않는다면 전원 빙고 완료는 권장이 아니라 도전 목표로 운영하세요. 승점 조건은 전원 빙고를 요구하지 않습니다.
- 동점 시: (1) 암살 성공 횟수 (2) 개인 미션 성공 횟수 (3) 동일 공동 순위.

| 종류 | 목표 | 성공 보상 |
|---|---|---:|
| 선물 배달부 | 서로 다른 2명에게 선물 전달 | 3점 |
| 통 큰 선물 | 서로 다른 3명에게 선물 전달 | 4점 |

| 질문 폭격 | 서로 다른 3명에게 질문 | 4점 |
| 인맥왕 | 서로 다른 3명과 악수 | 3점 |
| 악수 수집가 | 서로 다른 4명과 악수 | 4점 |
| 카드 상인 | 서로 다른 2명과 카드 교환 | 3점 |
| 거래의 달인 | 서로 다른 3명과 카드 교환 | 4점 |
| 철벽 인간 | 악수 없이 다른 행동 3회 | 4점 |

## 현장 준비물

- 플레이어 휴대폰과 안정적인 Wi-Fi/데이터, GM 노트북/태블릿 (권장)
- 선물 카드와 질문 카드 **합계 최소 참가 인원 × 6장** (20명 기준 최소 120장). 60장씩 준비하면 균형이 맞습니다. 카드 내용은 별도로 제작하세요.
- 10분 타이머, 빙고판은 사이트에 자동 생성.

## 기술 구성

외부 라이브러리 없는 Node.js HTTP 서버 + 브라우저 JavaScript. 약 1.8초 간격의 짧은 폴링 방식으로 기록 공유. 상태를 서버 JSON 파일에 보존. 방 PIN 및 개별 기기 토큰으로 참가자 미션을 분리. 게임 중 특정 참가자가 폰을 바꾸거나 브라우저 저장 공간을 삭제하면 신원을 복구할 수 없으므로 미리 주의해야 합니다. 서버가 정상 동작하는 한 20명 × 폴링은 가벼운 부하입니다. 외부 공개 전 HTTPS 사용과 현장 리허설을 권장합니다.

## 암살 미션 이름 (v1.1)

암살 미션은 아래 네 종류이며 게임 내 비밀 카드와 라운드별 결과에 모두 이름이 표시됩니다. 실제 성공 판정은 기존 네 가지 행동 유형을 그대로 사용합니다.

| 행동 | 암살 작전명 | 성공 조건 |
|---|---|---|
| 선물 | 폭발물 배송 | 지정 대상에게 선물 카드 전달 |
| 질문 | 치명적인 심문 | 지정 대상에게 질문 카드를 건네 질문하고 답변받기 |
| 악수 | 맹독의 악수 | 지정 대상과 악수 |
| 카드교환 | 죽음의 거래 | 지정 대상과 카드 1장씩 교환 |

## 수정 내용을 바로 확인하는 방법

`npm start`를 실행하고 `http://localhost:3000`에 접속하세요. HTML·CSS·JS 수정은 브라우저 새로고침으로 바로 볼 수 있습니다. 서버 `server.js` 변경은 서버 재시작 후 반영됩니다. 휴대폰까지 같은 화면을 보려면 PC와 휴대폰을 같은 와이파이에 연결하고 PC의 로컬 IP 주소와 포트 3000으로 접속하세요. 외부 인터넷에서 여러 사람이 접속하는 공개 링크를 쓰려면 별도 배포가 필요합니다. 같은 대화에서 계속 수정 사항을 요청하면 프로젝트 파일의 새 ZIP 버전을 제작할 수 있지만, 여기서 호스팅 중인 실제 웹사이트를 직접 변경하는 것은 아닙니다.
